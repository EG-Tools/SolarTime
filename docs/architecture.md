# Solar Time 구조와 상태 소유권

## v0.77 번역·그림자 소유권

- 별자리 카드의 이름과 설명은 `i18n/locales/*`의 기존 `bodies` 네임스페이스가 소유합니다. `sky.js`는 좌표·연결선과 고정 영문 분류만 소유하며 별도 번역 문구를 두지 않습니다.
- 일식 표시는 렌더러의 기존 위성 위치 캐시와 물리 반지름을 재사용합니다. 허용 조합은 달→지구, 유로파→목성뿐이며, 크기·궤도 간격의 시각적 과장에 따라 일식 위치를 바꾸지 않습니다.
- 표면 렌더러는 분석적 그림자 원뿔을 기존 패스에 적용합니다. 경계는 픽셀 크기에 맞춰 부드럽게 처리하고 최대 어두워짐은 38%로 제한합니다. 추가 그림자 맵·텍스처 샘플·그리기 호출은 없습니다. 직접 GPU·워커 GPU·CPU 경로가 같은 계산을 사용합니다.
- 토성 고리와 파편의 그림자는 `surface-style.js`의 공통 함수가 소유합니다. v0.77에서는 기존 어두워짐 강도 0.702를 0.6318로 줄였으며 경계 폭은 유지합니다.
- 안드로메다 데칼 원본은 `assets/backgrounds/andromeda-atlas.webp`에 보관하고 정식 내용 해시 URL로 배포합니다. 배경 파노라마는 기존 원본을 유지합니다.

이 문서는 기능 이름보다 상태 소유권과 의존 방향을 우선합니다. 파일을 더 만드는 것만으로 모듈화가 완료되지는 않습니다. 하나의 변경 가능한 상태를 한 책임자가 관리하고, 다른 영역은 공개 명령과 읽기 전용 결과로 연결해야 합니다.

좌측 별 버튼과 `*` 단축키는 app의 `toggleConstellations()`를 공유하고, 표시 상태는 기존 Sky의 master 값 하나를 사용합니다. 새 설정은 master OFF이며 개별 별자리는 표시 대상에 포함합니다. 저장된 개별 제외 목록과 master 상태는 복원합니다. 좌우 조작 패널은 같은 idle 담당자가 숨김·키보드 접근 상태를 함께 관리합니다.

## 기본 원칙

일반 보기의 전체 궤도 간격은 태양–수성부터 바깥 행성까지 적용하며 달·유로파의 로컬 궤도에는 적용하지 않습니다. 태양 카드의 수성 간격은 100% 크기에서도 조절할 수 있습니다. `localOrbitRadius()`가 태양–수성·지구–달·목성–유로파의 양쪽 표면과 여백을 보호합니다. `solarOrbitOffset()`은 수성의 이동량을 모든 주 궤도 반지름에 동일하게 더하므로 인접 궤도 간격을 보존합니다. CPU 위치와 GPU 궤도선은 같은 오프셋을 사용하고, 오프셋은 draw uniform으로 전달하여 카메라 이동 시 정점 버퍼를 다시 만들지 않습니다.

음원만 추가할 때는 `node tools/build-assets.cjs --music-only`로 기존 자산 처리기의 MP3 수집·해시 생성을 재사용합니다. 텍스처와 로컬 미리보기 메타데이터를 유지하며, 새 음원 객체만 기존 R2 업로드 도구로 올립니다. 배경음악 목록은 app의 `MUSIC_TRACKS`, 셔플·자동 전환·재시도는 `MusicPlayer`가 소유합니다.

별자리 해설은 정적 영어 페이지 `constellations.html`에서 제공하고, 조작법은 `guide.html#constellations`가 소유합니다. 해설 그림은 `node tools/build-constellation-guide.cjs --write`로 `SolarSky.FEATURES`의 좌표·이음선을 재사용해 생성합니다. 좌표를 복제하거나 문서 페이지에서 3D 렌더러를 실행하지 않습니다. 카탈로그 변경 후 그림을 갱신하며, 검증은 대상 누락과 오래된 그림을 검사합니다.

1. UI는 사용자의 의도를 명령으로 전달하며 카메라·파티클·여행 객체의 내부 값을 직접 바꾸지 않습니다.
2. 오프닝·워프·행성 여행은 공통 카메라 이동과 파티클 시스템을 조합하는 연출입니다.
3. 연출이 바뀌어도 기존 객체의 종류, 좌표계, 수명 시계를 바꾸지 않습니다.
4. 행성별 차이는 프로필과 선택 기능으로 선언합니다.
5. 렌더러는 계산된 장면을 그리며 다음 연출을 결정하지 않습니다.

## 목표 의존 방향

일반 궤도 확대 시 카메라 원근 기준 거리는 `dollyDistance()`가 외곽 궤도를 포함하도록 결정합니다. CPU 투영, GPU 궤도의 이동 계수, 추적 앵커 보간, 워프 출발 자세는 같은 기준을 공유합니다. 태양 300%·전체 간격 400%에서도 후퇴할수록 궤도가 연속해서 작아지고 기본시점은 해왕성 궤도 너비 65%를 유지해야 합니다.

```text
UI / app
    ↓ 명령
연출 전환 관리자
    ├─ 오프닝 연출
    ├─ 워프 연출
    └─ 행성 여행 연출
          ↓ 조합
    카메라 이동 / 파티클 생명주기 / 장면 등장 / 고리 시스템
          ↓ 장면 상태
    렌더러 / 표면 렌더러 / 하늘 렌더러

천체 카탈로그와 연출 프로필은 각 시스템에 읽기 전용 데이터를 제공합니다.
```

상위 계층은 아래 계층을 호출할 수 있지만, 아래 계층이 UI 설정을 읽어 다음 연출을 선택해서는 안 됩니다. 예를 들어 워프는 오프닝 설정을 직접 확인하지 않고 전환 관리자가 전달한 목적지 계획만 실행합니다.

## 파티클 전환 불변 조건

일반 카메라의 `project()`도 `occlusionDepth`를 제공하며, 천체 그리기 순서와 입자 가림은 이 카메라 기준 깊이를 공유합니다. `clipW`는 확대율 계산에만 사용합니다. 후퇴·오프닝의 `dolly<1`에서는 W와 깊이의 관계가 반전되므로 W로 앞뒤를 정하면 수성·달·유로파가 부모 천체를 뚫고 보일 수 있습니다. 토성 여행은 기존 여행 카메라의 깊이를 유지합니다.

고정 별자리 주변의 배경 밝기는 `sky.js`의 `buildFeatureQuietMask()`가 512×256 단일 채널 마스크로 한 번 계산합니다. 초기화 중 계산을 16행씩 나누어 브라우저에 제어를 돌려주며, 배경 셰이더는 완성된 마스크를 샘플링합니다. 원본 파노라마와 배경 별의 제외 규칙은 변경하지 않습니다. GPU 컨텍스트 복원 시 캐시에서 텍스처를 재생성하고 해제 시 함께 삭제합니다. 호환 렌더러는 기존 수식을 사용합니다.

오프닝·토성 입자의 대체 이미지 준비는 `renderer.js`의 `flightParticleSprite()`를 공유합니다. 입자별 투영·색상 합성·수명은 각 연출의 기존 경로를 유지합니다.

일반 화면과 고리 여행은 같은 `Sky.decorate()`로 별자리·반짝임·혜성을 그립니다. 여행에서도 이 호출을 생략하지 않으며, 상단 2D 레이어는 기존 `drawParticlePass()`의 불투명 천체 마스크를 사용합니다. 카메라로 별자리를 전환할 때 이전 포인터 hover를 해제하고, 임시 선 표시와 고정 표시의 수명은 계속 Sky가 소유합니다.

별자리 추적의 태양계 대표 점과 복귀 동작은 아래 「별자리 표시와 반짝임」 규칙을 따릅니다. 표시와 카메라 진입 상태를 별도로 중복 관리하지 않습니다.

북극성의 원은 hover 또는 명시적인 표시 ON 상태에서 유지됩니다. OFF이고 커서도 벗어나면 기존 감쇠로 사라지며 단축키만으로 원이 켜지지는 않습니다. 반지름은 글로우 렌더러가 제공하는 실제 표시 범위로 계산합니다.

오프닝→여행 카메라는 `captureOpeningFlight()`의 위치·자세·속도·가속도를 여행 경로 소유자에게 넘깁니다. `ring-tour.js`의 `OPENING_CARRY`는 이 차이를 감쇠해 기존 S커브에 연결합니다. 2.5초에 보정 위치를 강제로 0으로 되돌리지 않으며, 4초 전에 C2 연속으로 정리하여 먼 거리의 잔여 보정이 고리 안착에 영향을 주지 않게 합니다. 경로 진행 시각과 뱅크는 기존 공통 규칙을 그대로 사용합니다.

접근 중 ESC·Home으로 되돌아갈 때도 목적지의 위치·자세·FOV·원근 비율을 함께 인계합니다. `rewindPose()`가 원근 비율을 빠뜨리면 여행 렌더러의 마지막 프레임과 일반 렌더러의 첫 프레임에서 천체 크기·궤도가 달라집니다. 복귀 검사는 최종 카메라 값뿐 아니라 전환 양쪽의 화면 좌표와 크기도 비교합니다.

고해상도 텍스처 업로드는 `surface.js`의 기존 `DirectRenderer`가 소유합니다. 2048×1024 이상은 프레임당 최대 512K 픽셀씩 전송하며, 여러 로딩 작업도 하나의 업로드 대기열을 공유합니다. 완성 전까지 기존 텍스처를 유지하고, 취소·세대 변경 시 임시 비트맵과 미완성 텍스처를 해제합니다. 카메라 전환 모듈에 별도 텍스처 캐시나 준비 타이머를 추가하지 않습니다.

- 활성 필드는 현재 연출 하나가 소유합니다.
- 연출이 바뀌면 기존 필드는 소멸 목록으로 이동해 원래 좌표와 운동을 유지합니다.
- 목적지 필드는 수명 `0`에서 새로 시작합니다. 출발 필드의 이동 속도는 받을 수 있지만 경과 시간과 입자 배열은 받지 않습니다.
- 출발 파티클을 목적지 좌표로 복제하거나 살아 있는 입자의 투영 방식을 바꾸지 않습니다.
- 소멸이 시작된 필드는 자연 종료 조건보다 소멸 시간을 우선하며, 알파가 끝날 때 제거합니다.
- 필드 전체 알파를 동시에 낮추지 않습니다. 필드 밝기는 인계 순간 값을 유지하고, 고정된 입자별 소멸 시차와 곡선으로 무리를 분산해 제거합니다.
- 인계를 기다리며 우회한 기존 등장·도착 감쇠식은 소멸 중 다시 켜지지 않습니다. 소멸 구간의 알파 소유자는 입자별 소멸 곡선 하나입니다.
- 현재 구현의 `FlightParticleLifecycle`이 활성 필드와 소멸 필드 목록을 소유합니다. 오프닝→토성 및 토성→워프가 같은 규칙을 사용합니다.
- 입자 프로필은 생성량·크기·색·글로우·꼬리·속도·등장 및 소멸 곡선을 소유하고, 카메라 경로는 소유하지 않습니다. 오프닝과 토성 진입은 서로 다른 화면 성격을 가지므로 각자의 프로필과 투영 방식을 유지합니다.
- 토성 진입 프로필은 `applySaturnEntryParticleProfile()` 한 곳에서 입자 풀과 표시 집단을 구성합니다. 오프닝 전용 값을 토성 진입에 덧씌우거나 살아 있는 필드를 다른 카메라 좌표계로 옮기지 않습니다.

카메라 경로가 바뀌는 프레임에는 위치·자세와 함께 속도·가속도를 전달합니다. 다음 경로는 이 값을 하나의 유한한 브리지에서 흡수하고, 별도의 보정 트윈이나 두 번째 거리 시계를 만들지 않습니다.

일반보기와 실제비율은 양방향 모두 2초 동안 전환합니다. 비율 전환이 끝난 뒤 기존 `0`번의 공통 Home 카메라 전환을 한 번 시작합니다. Home은 해왕성 궤도의 화면상 가로 폭을 뷰포트의 65%, 태양의 세로 위치를 57%에 맞추며 현재 좌우 방향과 회전 의도를 유지합니다. 반대 전환이나 직접 카메라 입력의 취소도 기존 전환 소유자가 처리합니다.

고리 자원 준비는 `prepareRingTourResources()` 한 경로로 일반 오프닝과 토성 오프닝에서 시작합니다. 완성된 입자 풀·GPU 자원은 일반 카드 진입에도 인계하고, 정상 복귀 후에는 한 벌만 보관해 다음 여행에 재사용합니다. 카메라 경로·시각·뱅크는 재사용하지 않습니다. `KHR_parallel_shader_compile` 지원 시 프레임별 완료 확인으로 컴파일을 기다리며, 미지원 또는 즉시 본체 렌더링이 필요한 경우 기존 동기 경로로 처리합니다. 취소 시 준비 중인 셰이더도 해제합니다.

별자리 모드의 축소 태양계는 합성 캔버스 해상도만 표시 배율에 맞춰 최대 절반으로 줄입니다. 월드 좌표·개별 행성 스케일·GPU 깊이 계산은 변경하지 않고, 복귀할수록 합성 해상도를 원래 크기로 복원합니다.

## 행성과 고리 구성

모든 행성은 공통 로컬 좌표 프레임을 가집니다. 고리·대기·위성계·표면 경로·여행 프로필은 선택 기능입니다.

```text
천체
 ├─ 로컬 좌표 프레임
 ├─ 대기 프로필?
 ├─ 고리 프로필?
 ├─ 위성계?
 ├─ 표면 경로?
 └─ 여행 프로필?
```

토성과 천왕성은 고리 계산·렌더링 엔진을 공유하되 맵 소스, 안쪽·바깥쪽 반지름, 밀도, 파편 크기, 색상과 LOD는 각각의 프로필이 정합니다. 고리가 없는 행성에는 숨겨진 고리 객체를 만들지 않습니다.

토성 여행의 현재 경로는 다음 프로필로 보존합니다.

- 접근: S커브
- 안착: 고리 접선
- 주행: 고리 순환
- 탈출: 나선
- 복귀: 여행 시작 전 카메라

다른 행성 여행은 같은 단계 인터페이스를 사용하되 경로 조합을 독립적으로 선택합니다.

일반 카메라와 여행 카메라의 인계는 화면 위치만 맞추지 않고 동차 투영 전체를 전달합니다. 실제 크기 모드는 화면 배치 좌표와 물리 깊이가 서로 다를 수 있으므로, 토성 하나의 깊이로 주변 천체를 근사하지 않습니다. 여행 중 원거리 천체의 점 표시와 GPU 행성 합성 순서는 보정 전 카메라 깊이를 공유합니다. 일반 화면에서는 동차 깊이를 사용하고, 해당 값이 없는 직교 투영에서만 화면 배치용 Z를 보조 순서로 사용합니다.

여행 본체는 셰이더에서 광선과 구의 교차로 그리므로, 중심 좌표와 반지름으로 만든 화면 원으로 가림 영역을 근사하지 않습니다. `particleSphereMask()`와 `traceSphereMask()`가 실제 여행 카메라의 구 윤곽을 소유하며, 연출 입자와 원거리 천체 점 표시가 이를 공유합니다. 점 천체는 본체 뒤에 있을 때만 전체 코어·글로우를 가리고, 앞에 있는 천체와 투명한 고리는 유지합니다. 브라우저 검사는 실제 여행 셰이더의 불투명 픽셀과 Canvas 점 표시를 비교합니다.

## 현재 구조에서 유지할 모듈

천문 계산, 표면 렌더링, 하늘, 에셋·재질, 성능 정책, 번역·설정, 음악·알람·타이머는 이미 별도 책임을 가지고 있습니다. 일관된 모양을 만들기 위해 이들을 다시 합치거나 불필요하게 나누지 않습니다.

## 단계적 정리 순서

1. 현재 화면과 전환을 회귀 검사로 고정합니다.
2. `app.js`의 렌더러 내부 필드 변경을 공개 전환 명령으로 교체합니다.
3. 카메라 자세·속도·뱅크 인계를 한 인터페이스로 통합합니다.
4. 파티클 생성·수명·프로필을 렌더러 그리기와 분리합니다.
5. 토성 여행 경로와 고리 렌더링을 분리하고 공통 행성 여행 인터페이스를 둡니다.
6. 토성·천왕성 고리를 데이터 프로필로 이동합니다.
7. 검증된 교체 경로의 중복 분기와 미사용 코드를 제거합니다.

각 단계는 화면 동작을 유지하는 작은 변경으로 진행합니다. 새 구조가 기존 구조 위에 병렬로 남지 않도록 교체가 끝난 경로는 같은 단계에서 제거합니다.

## 별자리 표시와 반짝임

`sky.js`의 `SKY_FEATURES`가 별 좌표·연결선·한글 카드를 함께 소유하며 `SolarSky.FEATURES`로 공개합니다. 항성 위치는 HYG 4.1/SIMBAD 좌표를 사용하고, 연결선은 Stellarium Western sky culture의 HIP 경로를 기준으로 유지합니다. IAU가 공식화한 것은 별자리 경계이므로 이 연결선은 서양식 인식 도식이며 경계 데이터로 취급하지 않습니다. `app.js`는 이 목록의 중심 방향과 공유 항성을 이용해 가까운 대상부터 이어지는 좌우 순환을 한 번 생성합니다. 북두칠성·북극성 항목과 황도 12궁, 큰곰·작은곰·카시오페이아·오리온·백조·페가수스·안드로메다·남십자자리를 포함한 스무 별자리를 함께 유지합니다. 큰곰자리와 북두칠성, 작은곰자리와 북극성, 페가수스자리와 안드로메다자리는 동일 항성 객체를 공유하고, 한 프레임에서 항성과 겹치는 연결선은 한 번만 그립니다. 북극성의 푸른빛 흰색 원은 단일 항성 표시 프로필이며 선과 동일한 표시 수명을 사용합니다. 원 지름은 해당 별의 표시 크기를 따라 약 두 배로 변화합니다.

별자리 카드의 한글 제목과 좌우 이동 이름은 분류 문구와 중복되는 `자리` 접미사를 생략하고, 행성용 수치 정보 영역은 별자리 카드에서 숨깁니다. 별자리 추적 중 좌우 대상 전환은 공통 카메라 트윈이 좌·우·랜덤 회전 의도를 잠시 보관했다가 그대로 재개하므로 회전 토글 상태를 바꾸지 않습니다.

행성 본체의 공통 점 LOD는 화면 지름만 기준으로 삼습니다. 지름 2px에서는 최소 텍스처 본체만 표시하고, 2px에서 1px 사이를 연속적으로 전환한 뒤 지름 1px부터 점입자로 표시합니다. 행성 종류·카메라·DPR에 따른 별도 임계값은 두지 않습니다.

배경 천구 파노라마의 시작 경도는 고정하며 별자리와 같은 천구 좌표계를 사용합니다. 로컬과 공개 화면 모두 원본 `universe-optimized.webp`의 기존 해상도 단계와 파노라마 표본 방식을 사용합니다. 은하 아틀라스와 선택 셀은 공통 매니페스트에서 관리해 로컬과 공개 URL의 에셋 경로가 일치합니다. 별도 투명 아틀라스의 첫 셀만 작은 M31 데칼로 J2000 방향에 표시하며, `galaxyIndices: [0]`으로 장식 은하 둘은 제외합니다. 원본 이미지 재합성·리사이즈 없이 기존 `loadGalaxyAtlas()`와 `drawGalaxies()`를 재사용합니다.

8개 중첩 영역으로 합성한 배경 시안과 `tools/build-sky-mosaic.cjs`는 실험 기록으로만 보관합니다. 사용자 결정에 따라 원본 배경의 색상과 무늬를 유지하며 시안을 자동 적용하지 않습니다. GPU 세부 로딩은 매니페스트와 장치 한계를 따르고 현재 원본의 최대 단계는 2048입니다.

별자리 추적 배율은 사용자 선택에 따라 1.2배를 유지합니다. 카탈로그의 중심 방향을 공통 카메라 자세 계산에 전달하며, 큰 별자리는 일부 잘림을 허용합니다. 자동으로 렌즈를 넓히거나 별 좌표를 축소하지 않습니다.

`sky.js`가 별자리 이음선의 개별 표시 상태·선 연결·임시 표시·별별 반짝임을 소유합니다. 여러 항목이 함께 표시되면 선택·추적·호버 대상을 청백색으로 우선 표시하고 나머지는 황금색으로 구분합니다. 공유 항성과 선의 단일 그리기 규칙은 그대로 유지합니다. `renderer.js`는 카메라 추적 대상과 진입 전 카메라 하나를 소유하고 `setFeatureTracked()` 공개 명령으로 화면 밝기 상태만 전달합니다. `app.js`는 Preferences에 개별 표시 목록과 상위 표시 상태를 따로 저장·복원합니다. 추적 카메라와 호버는 저장하지 않습니다.

카탈로그 별자리는 배경 천구 반지름의 99% 깊이에 고정합니다. 일반 배경 별의 앞뒤 깊이 움직임은 별자리에 적용하지 않으며, 별자리의 생동감은 위치 이동이 아닌 별별 크기·알파·반짝임 주기로 표현합니다.

`*`는 개별 이음선 선택 위의 상위 표시 스위치입니다. OFF는 선택 목록을 보존한 채 모든 이음선을 숨기고, 다시 ON하면 사용자가 개별적으로 켜 둔 이음선만 복원합니다. 개별적으로 꺼 둔 별자리를 임의로 켜지 않으며 이 상위 상태도 저장합니다. 카메라는 이동하지 않습니다. 과거 보기 1단계와 화면 분할점 배치는 제거했습니다. 카드의 `별자리 보기`/`태양계 보기` 토글 또는 뷰포트 별자리 더블클릭만 중앙 추적(기존 보기 2단계)을 시작합니다. 카드의 `이음선 표시` 토글은 모든 별자리 카드 최하단에 두고 그 아래 구분선도 만들지 않습니다. 추적 중 좌우 입력은 천구에서 가까운 다음 별자리를 중앙에 배치하고 최초 복귀 카메라를 유지합니다. 추적하지 않는 별자리 카드의 좌우 입력은 같은 공간 순환에서 카드 대상만 전환하고, 버튼 도움말에는 대응하는 `←`·`→` 키를 표시합니다. 일반 태양계 모드에서는 행성, 지구 지역 보기에서는 국가를 전환합니다. 지구가 추적 크기보다 작으면 지역과 시간만 바꾸며, 가까이 보는 상태에서부터 카메라도 해당 지역으로 회전합니다.

새로고침 오프닝의 첫 프레임에서 `sky.js`가 저장된 표시 ON 별자리의 페이드·순차 연결 시계를 시작합니다. 오프닝 종료나 토성 인계 때 선을 다시 시작하지 않습니다. 워프는 같은 상태 소유자에게 별도 종류로 전달하며 선 표시와 연결 시계를 유지합니다. 워프 복귀의 배경 회전 보정은 일반 별과 카탈로그 별에 동일한 축을 적용하고 6초 동안 고정 천구 좌표계로 수렴합니다. 영구적으로 별자리 좌표를 회전시키지 않습니다.

별자리 카드의 표시 토글이 꺼져 있으면 크기는 70–100%, 켜져 있으면 100–130% 범위에서 변합니다. 별별 고정 시드로 6.5–15.5초 주기와 위상을 달리하며, 알파는 80–100% 범위입니다. 표시 전환은 기존 알파 페이드로 두 크기 범위를 보간하고 진행 중인 위상을 초기화하지 않습니다. 크기와 반짝임은 렌더러의 애니메이션 시간을 사용하므로 일시정지 뒤에도 이어집니다. UI 페이드는 실제 시간을 사용하고 빠른 재전환은 현재 불투명도에서 이어집니다. 공유 항성과 선의 소유자 레코드는 재사용하되 우선순위는 매 프레임 갱신합니다.


### 별자리 배치와 가벼운 안내선

카메라 자세와 기울기는 기존 카메라 전환의 bankFrom/bankTo로 보간하며 추적 종료 시 최초 자세로 돌아옵니다. 별자리마다 별도 전환 경로나 복귀 상태를 만들지 않습니다. 추적 중에는 1.2배 고정 배율로 좌클릭 회전만 허용합니다.

고정 카탈로그의 공통 연결선 키는 스크립트 로딩 시 한 번 계산합니다. 화면 좌표는 카메라 축·배율·관측자 위치·창 크기가 같을 때 재사용합니다. 선 표시 여부나 별의 반짝임은 이 좌표 캐시를 무효화하지 않습니다. 부팅을 막는 화면별 선행 렌더링은 하지 않습니다.

별자리 안내선은 행성 정렬과 같은 얇은 연결선 표현을 사용합니다. 화면 크기의 shadowBlur나 전용 글로우 캐시는 사용하지 않습니다. 각 별자리의 선을 한 경로로 그리며 0.3초 순차 연결과 표시·해제 페이드는 유지합니다. 표시 ON 선은 각자 다른 위상의 10초 주기로 밝기 70~100%를 반복합니다. 겹침 여부와 관계없이 선택·호버·추적 중인 별자리는 청백색과 기존 대비 110% 강도로, 선택되지 않은 이음선은 황금색과 70% 강도로 0.7초 동안 전환합니다. 공유 항성과 선의 단일 그리기 규칙은 유지하며 북극성 원도 같은 규칙을 따릅니다. 마우스가 벗어나면 진행 중인 idle 주기로 복귀하고, 이미 ON인 선은 호버로 다시 그리지 않습니다. 표시 토글에 포커스가 있어도 좌우 방향키는 별자리 전환에 전달합니다.

별자리 보기에서는 태양계를 원래 좌표에 유지한 채 숨깁니다. 진입·복귀 전환 중에만 행성·고리·궤도·이름을 임시 캔버스 한 장으로 합성해 같은 비율로 축소·확대하고 알파를 보간합니다. 실제 천체 크기·궤도·깊이는 바꾸지 않으며, 내부 가림을 완료한 장면에만 알파를 적용합니다. 배경 별자리와 여행 파티클은 합성 밖에 두고 파티클 가림 영역만 같은 화면 비율로 맞춥니다. 전환이 끝나면 임시 버퍼를 해제합니다. 완전히 숨긴 동안 대표 점·복귀 원·선택 영역은 없습니다. 별자리 추적은 기존 관측 거리와 pan을 유지하며 방향과 1.2배 배율만 설정합니다.

별자리 보기 종료 명령은 기존 소유 경로를 재사용합니다. `0`과 `ESC`는 같은 `reset` → `animateHome` 경로로 기본시점에 복귀합니다. 토성 여행 버튼은 `replayOpening`에 토성 오프닝과 기본시점 목적지를 전달하여 워프 → 기본시점 도착 오프닝 → 기존 S커브 토성 진입으로 연결합니다. `T`도 같은 워프를 사용하며, 별자리 보기에서는 오프닝 없음 설정이어도 실제 워프와 기본 도착 오프닝을 실행합니다. 일회성 목적지 지정은 저장된 오프닝 설정을 변경하지 않습니다. 기존 추적 버튼 해제는 저장된 카메라로 복귀합니다. 숨겨진 태양계의 더블클릭 경로는 없습니다.

태양계 가시성은 `solarSceneHidden`에서 전환 완료 값과 기존 워프 시각으로 판정합니다. `skySolarMix`와 `solarSceneAppearance`가 합성 화면의 알파·배율을 함께 결정하며 개별 물체를 수정하지 않습니다. 별자리 모드의 `skySolarDisplay`가 켜져 있으면 같은 합성 장면을 태양 중심으로 5%까지 축소하고, 꺼져 있을 때만 기존처럼 숨깁니다. 따라서 천체별 사용자 크기·궤도 설정은 바뀌지 않으며 복귀 때 합성 배율만 100%로 돌아옵니다. 축소 태양계의 hover 원과 더블클릭 복귀도 이 합성 장면이 계산한 단일 화면 경계를 사용합니다. `advanceSkySolar`만 전환 값을 갱신합니다. 수동 회전으로 카메라 이동을 취소해도 기존 tween의 시계 참조를 유지해 전환은 끝까지 진행하며, 일시정지 보정은 공통 시계 레지스트리에서 중복 없이 적용합니다. 워프 출발·루프 동안 숨김을 유지하고 도착 오프닝부터 장면이 나타납니다. 숨김 분기에서도 입자 패스는 실행하며, 숨긴 행성은 입자 가림이나 워프 출발 종료 판정에 사용하지 않습니다.

호버 해제 시 선은 현재 알파와 그려진 길이를 유지한 채 2초 동안 감소합니다. 다른 별자리로 바로 이동해도 이전 선의 종료 시계를 보존합니다. 표시 ON 상태의 선은 지워지지 않고 호버 강조만 같은 시간에 걸쳐 기존 idle로 돌아갑니다. 표시 토글 자체의 기존 페이드 시간은 유지합니다.

하단 footer의 투명한 배치 영역은 포인터 입력을 가로채지 않습니다. 실제 링크·버튼과 가로 스크롤용 행성 메뉴만 입력을 받으며, 빈 공간 아래의 천체는 공통 최소 클릭 범위로 선택합니다. 명왕성 전용 선택 분기를 추가하지 않습니다.

### 먼 여행 복귀와 태양 광채 계산

토성 여행과 일반 카메라의 투영 보간은 두 행렬의 동차 좌표 정규화를 먼저 맞춥니다. 여행 시작 거리 단위와 기본 카메라 단위가 다르다고 주변 행성의 보간 비중이 달라지지 않도록 하며, 근접 절단값도 같은 여행 단위로 변환합니다. 물체 크기나 궤도를 임시 변경하지 않습니다.

태양 광채의 프레임 공통 회전·알파 계산은 정점 셰이더에서 수행합니다. 확대된 태양의 불투명 내부에서 원래 폐기되던 픽셀은 외곽 사각 구간만 그려 계산을 생략합니다. 작은 태양과 기존 scissor 사용 중인 경로는 단일 quad를 유지합니다. 독립 GPU 검사에서 이전 영상과 픽셀 차이는 최대 2/255였으며, 4K 근접 광채 패스 시간은 해당 측정 조건에서 약 16~32% 감소했습니다. 전체 앱 FPS 개선율을 뜻하지 않습니다.

별자리 회전 중에도 중복 항성은 한 번만 투영합니다. 화면 밖 별자리의 그리기 소유권 계산과 알파 0인 선의 연결 계산을 생략하며, 화면을 가로지르는 선은 보수적인 경계 검사로 유지합니다. 선 연결 그룹은 카탈로그 로딩 시 캐시하고 표시 알파는 별 단위가 아닌 별자리 단위로 계산합니다. 동일 회전 경로 비교에서 별자리 처리 평균 0.255ms → 0.1875ms, 검사 화면 픽셀 차이 0을 확인했습니다. 이는 전체 프레임 개선율이 아닙니다.
